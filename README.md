# Veedu · வீடு

A shared household app for two people: **pantry inventory**, **shopping list**, **trip lists** (gifts for the India trip) and **to-dos**, synced live between both phones.

Built with Expo (iOS, Android, web) and Supabase (auth, Postgres, realtime).

## How it fits together

- Each person signs in with an emailed one-time code, then creates a household or joins one with an invite code.
- **Pantry and shopping are linked in the database** (`supabase/migrations`):
  - when a pantry item's count drops below its *keep at least* level, it is added to the shopping list with the amount to buy;
  - checking a linked shopping item off adds that amount back to the pantry (unchecking undoes it);
  - a shopping item typed by hand is linked to the pantry item with the same name.
- Repeating to-dos create their next occurrence when checked off.
- Every change is pushed to the other phone through Supabase Realtime.

## Set up

1. Create a free project at [supabase.com](https://supabase.com).
2. In the SQL editor, run `supabase/migrations/20261118000000_init.sql` (or `supabase db push` with the Supabase CLI).
3. **Auth → Email templates → Magic link**: include the code so people can type it in, e.g. `Your Veedu code is {{ .Token }}`.
4. Copy `.env.example` to `.env` and fill in the project URL and anon key (Project Settings → API).
5. Install and run:

```bash
npm install
```

```bash
npx expo start
```

Open it in Expo Go, an iOS simulator, an Android emulator, or press `w` for the web.

## Building for phones

Builds run in the cloud with [EAS](https://docs.expo.dev/eas/), so no local Xcode or Android Studio is needed. Profiles live in `eas.json`: `development` (dev client, internal), `preview` (internal install link) and `production` (store builds).

1. Sign in: `npx eas-cli@latest login`.
2. Link the project once: `npx eas-cli@latest init`. This writes `expo.extra.eas.projectId` into `app.json`; commit it.
3. Put your Supabase values in EAS so builds can reach the backend: `npx eas-cli@latest env:create --name EXPO_PUBLIC_SUPABASE_URL --value <url> --visibility plaintext` and the same for `EXPO_PUBLIC_SUPABASE_ANON_KEY`.
4. Try it on your phones: `npx eas-cli@latest build --profile preview --platform all`, then open the install link on each phone (iOS needs the device registered with `npx eas-cli@latest device:create`).

**iOS, TestFlight** (needs an Apple Developer account):

```bash
npx eas-cli@latest build --platform ios --profile production
npx eas-cli@latest submit --platform ios --latest
```

Then add testers in App Store Connect, under TestFlight.

**Android, Google Play internal testing** (needs a Play Console account; the first upload of an app must be done by hand in the console):

```bash
npx eas-cli@latest build --platform android --profile production
npx eas-cli@latest submit --platform android --latest
```

Add your testers' emails to an internal testing track in Play Console. For `submit`, create a Google service account key and reference it from `eas.json` under `submit.production.android.serviceAccountKeyPath`.

The app icon and splash are generated by `python3 scripts/generate-icons.py` (needs Pillow); edit the script and rerun to change them.

## Offline use

Lists open instantly and work without a connection: the data cache is saved on the device (AsyncStorage on phones, localStorage on web) and is cleared on sign-out and when the app version changes. Changes made offline are queued and replayed when the connection returns, and an "Offline" banner shows meanwhile.

```bash
npm run typecheck
```

```bash
npx expo lint
```

```bash
npm test
```

```bash
npm run test:db
```

`test:db` spins up a throwaway local Postgres (needs `initdb`/`pg_ctl`/`psql`), applies the migrations on top of a small stub of Supabase's `auth` schema, and runs the behaviour tests in `supabase/tests`.

## Layout

```
src/app/                 routes (Expo Router)
  sign-in.tsx            email code sign-in
  onboarding.tsx         create or join a household
  (app)/                 everything behind sign-in
    (tabs)/              Home, Pantry, Shop, Trips, To-do
    settings.tsx         invite code, members, names, sign out
src/features/<feature>/  data hooks (api.ts) and feature components
src/components/ui.tsx    shared UI building blocks
scripts/                 database test runner, icon generator
src/lib/                 Supabase client, session, realtime sync, pure domain logic
supabase/migrations/     schema, RLS policies, triggers, RPCs
supabase/tests/          database behaviour tests
```
